# UFI103S V03 Wi-Fi bring-up

The board exposes a WCN3620 2.4 GHz radio through WCNSS and the mainline
`wcn36xx`/mac80211 driver. The PHY advertises one stream and HT20 rates up to
72 Mbps; this is a PHY capability, not a throughput measurement. USB Ethernet
and its SSH configuration remain the management path. No router credentials or
access-point configuration are generated by this work.

## Source and firmware provenance

Linux remains based on stable v6.18.62. The installed minimal TF-A does not
provide Qualcomm PAS services. The kernel therefore adapts Stephan Gerhold's
[non-secure WCNSS direct-boot implementation](https://github.com/msm8916-mainline/linux/commit/96f0cb1f58190ce0cd997aa65d0cb0a3ab4c79cd)
from the MSM8916 maintainers' `wip/tf-a` branch. The board adds the matching GCC
WCSS reset and TCSR halt register. It keeps the other validated CPU/thermal,
USB/eMMC and LED settings; no boot-firmware or LK changes are required.

The backport includes fixes verified on this board:

- Hold WCNSS reset through firmware loading and release it before IRIS handshakes.
- Bound both IRIS handshake polls instead of spinning indefinitely.
- Preserve probe deferral while RPM power-domain suppliers arrive asynchronously.
- Select the real remaining vddpx supply when power domains cover cx/mx.

`scripts/extract-wifi-firmware.py` reads **local original-device backups** only.
It extracts `wcnss.mdt`/segments from the FAT16 modem backup and the board's
29,816-byte `WCNSS_qcom_wlan_nv.bin` from its ext4 persist backup. Its manifest
records source/file hashes. There are no runtime writes to modem or persist.
Radio firmware cannot currently be built from available source; the kernel,
boot/initramfs code and iw/libnl tools are source-built.

Do not publish the private firmware/calibration directory or boot images derived
from it. Redistribution rights have not been assessed. The public repository
and default CI export only source/configuration; OEM blobs remain excluded.
The signed regulatory database comes from the pinned upstream wireless-regdb
Git repository. iw/libnl/regdb source pins are in `configs/wifi-sources.json`.

## Local preparation

```sh
python3 scripts/extract-wifi-firmware.py
bash scripts/build-wifi-tools.sh
cp src/wireless-regdb-wifi/regulatory.db src/wireless-regdb-wifi/regulatory.db.p7s build/wifi/firmware/
bash scripts/build-kernel.sh
python3 scripts/pack-persistent.py \
  --artifacts build/ci-hardware-test/artifacts \
  --kernel build/linux/arch/arm64/boot/Image.gz \
  --dtb build/linux/arch/arm64/boot/dts/qcom/msm8916-qmodem-rescue.dtb \
  --firmware build/wifi/firmware --output build/wifi/boot
```

The packer checks the source rescue artifacts, preserves the approved public key,
allowlists private firmware paths and records local kernel/DTB/firmware hashes.
The image contains the firmware for early WCNSS startup. Debian also needs the
same files under `/usr/lib/firmware` because wcn36xx requests its NV file when the
interface comes up, after switch_root, and a radio restart reloads the firmware.
Do not reuse another board's calibration.

`deployment/wifi/qmodem-wifi-start` and `.service` initialize the radio after
local filesystems and udev. The helper can bind a late-probing WCNSS, start an
offline remote processor and raise wlan0. The unit skips kernels without the
driver and systems without the local firmware. It does not configure association,
DHCP, NAT or an AP. Future cloud roots install this source-only unit conditionally;
private firmware must still be supplied locally.

The persistent initramfs reserves a **32 MiB maximum** for /run; tmpfs allocates
only used pages. The previous 16 MiB limit caused systemd's service reload to
refuse its required 16 MiB free-space buffer.

## Hardware validation

The first direct-loader image booted the radio and scanned up to 20 BSS entries,
but stop/start exposed a reset-sequencing hang. A user-assisted physical replug
was required. That revision is superseded and must not be installed.

After correction, automatic startup and scanning passed after the user replug
and subsequent warm starts. Five controlled restarts passed with the initial
fix; further cycles passed on the later reset/load and regulator revisions. On
the final regulator-fixed candidate, automatic service startup, initial scan,
three stop/start/scan cycles, daemon reload, systemd health and LEDs-off checks
passed. The dummy vddcx supply warning is gone. Nearby SSIDs/BSSIDs are not
copied into source or published logs.

Current local records are `build/wifi/test-status.json`, `boot/manifest.json`,
`regulator-final-test.log`, the private firmware manifest and `boot-review.json`.
The final candidate is RAM-booted, with wlan0 administratively up but unassociated.
Association, AP operation, packet throughput and long-duration Wi-Fi stability
remain untested. Existing unrelated SCM/SMSM/USB warnings remain.

## Boot-only persistence review

The previous Debian boot image was preserved while the Wi-Fi candidate was RAM-tested.
A fresh off-device boot backup was independently hashed. The proposed Wi-Fi
boot image is padded to exactly 16 MiB, and its review includes both old/new
hashes, backup location and the protected partition baseline.

`scripts/update-wifi-boot.py` defaults to read-only preflight. Only after separate
exact-image approval, `--apply --approve-sha256 HASH` writes /dev/mmcblk0p22,
fsyncs and independently hashes the complete partition. It checks GPT and all
25 protected partition hashes before/after. It neither replaces userdata nor
changes LK/firmware. The installed boot still starts through the existing host
`fastboot continue` command. Preserve the known-good rescue and all backups.

## Approved boot update installed

The owner approved the exact 16 MiB Wi-Fi boot image. Its full-partition SHA256
is `83d499f0356874f221b13eaddd7c535004e297793359159639740c75d1efcba0`.
The updater wrote/readback-verified boot only; GPT and all 25 protected partition

remains under the local `backups/wifi-preinstall-*` directory.

Two installed starts through unchanged LK `fastboot continue` passed. The Wi-Fi
service started automatically, WCNSS was running, and real scans found 13 then
16 BSS entries. Systemd reported running with zero failed units; four CPUs were
online and LEDs off. The interface is administratively up but unassociated.
No router credentials or AP configuration have been supplied. Full association,
packet throughput and long-duration operation remain untested.

Local installation evidence is `build/wifi/boot-installation.json`,
